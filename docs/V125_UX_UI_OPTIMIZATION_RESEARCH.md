# AeroSim 1.25：UX、UI 与真实场景优化调研

日期：2026-10-10（America/Los_Angeles）。对象：现有产品文档 v1.6、macOS 1.0.0 开发候选08的已保存截图及当前工作区源码。开始时 HEAD：`241aa545ff3e35bd5c436bc7cadcdb37948496d3`；部分08业务源码尚未提交，源码观察不能自动等同于该构建的行为。

## 1. 结论

**需要优化，优先级是统一操作与安全状态 → 移动布局重排 → 场景材质/尺度/光照。** 不建议只缩小桌面页面，也不建议先给所有贴图提高分辨率。

本次为专家启发式审查、源码阅读和已有图像检查，不是用户访谈、可用性实验或新设备测试。报告提出下一批开发候选的建议与验收条件；不直接修改应用、不替用户批准机型、不把建议当成已实现功能。桌面仍以[PRD](../飞行模拟器产品设计文档.md)中的23张原始概念图为目标；若简化导航等建议改变原图结构，需要用户另行确认新目标，不覆盖原图来制造通过。

三路独立调查见：[UX流程](V125_UX_FLOW_AUDIT.md)、[UI与移动布局](V125_UI_MOBILE_AUDIT.md)、[场景与材质](V125_SCENE_REALISM_AUDIT.md)。随后另做文档与证据复核，不能用调研替代原生验收。

## 3. 优先问题与最小优化

P0为发布前必须关闭的输入/安全门禁，P1为核心易用性与画面质量，P2为后续精修；这是风险判断，不是实测严重度评分。

## 4. 简单明了，但不损失功能

建议统一四层：**主要任务 → 当前状态 → 必要下一步 → 高级细节**。同屏保留一个明确的主要CTA；可有始终可达的暂停/返回等安全动作，不以“一个按钮”限制安全能力。

- 首页：一个主要“Continue Training”；无进度时用“Start First Lesson”，显示真实已选控制/训练机状态。自由飞仍有独立可发现入口，不删用户已有功能。
- 机型：训练选择与外观审核两种上下文明确分开。现有运行机库为4种DJI近似原型＋2种通用训练机；141条研究审核目录不是已可飞目录。审核机型显示pending/有稿/无稿/待发布证据，详情含官方来源与介绍，不自动替用户批准。
- 飞行：任务步骤可折叠、核心遥测精简，扩展设置和详细遥测进暂停；双杆位置不被“更多”菜单或相机工具覆盖。暂停始终可发现，不能依赖隐藏手势。
- 双杆默认保持无人机Mode 2：左杆油门/偏航、右杆俯仰/横滚，三端相同；不为套用一般游戏习惯改成左移动/右相机。模式与通道设置改变后明确提示并重新验证，Position与Manual的运动反馈差异要在教程中解释。
- 结算/记录：结束后解释是否保存，继续练习与查看回放分开；返回记录保留筛选与位置。技术中断不写成正常完成或用户失败。
- 设置：控制、显示、场景画质、声音、语言/单位分组；UI Scale、HUD Scale、Text Size依现PRD独立即时预览并各自本地保存，成功/写盘失败如实提示，不改成点击Save才生效；不把大字实现为全屏放大。飞行参数、校准、任务和OSD编辑另用独立草稿与Apply/Save/Cancel，不能让其他页面的Save把未应用草稿间接落盘。其余设置须按分组冻结策略，不在本轮擅自把所有项改为同一保存模式。

对应的统一流程建议为：选择任务或自由飞 → 编辑会话草稿（复用现有合法选择） → 必要准备检查与摘要 → 飞行 → 结算 → 继续/回放。不同任务可省略不必要的页面，但“返回、取消、应用、保存、开始”的语义不变。

## 5. 三端布局建议（不是已完成效果图）

| 区域 | 电脑 | iPad可用空间宽/窄 | iPhone |
| --- | --- | --- | --- |
| 菜单 | 保留原图侧栏与内容区；桌面一致性单独验 | 宽时列表＋详情；窄窗口转单列与有文字导航，保留选择 | 单列列表→详情；精简且有标签的导航，不保留72px无文字侧栏 |
| 选机 | 筛选＋网格＋详情，按需3D预览 | 2栏候选/详情或单列；不固定设备型号判断 | 搜索/筛选入口＋卡片，详情全页；审核与可飞状态分开 |
| 飞行横屏 | 键盘/物理输入提示＋可显示双杆 | 双杆底部两侧，暂停顶边；任务/地图不占杆区 | 双杆两侧，顶部紧凑状态与暂停；详细遥测进暂停 |
| 飞行竖屏 | 不作手机等比缩图目标 | 场景与任务重排，双杆不重叠 | 上方场景，下方操控带；不能仅提示转横屏就声称竖屏支持 |
| 放大文字 | 重排/滚动，原图正常档和大字档分别验 | 窄窗切列，长标签换行，sheet/panel可滚 | 控件纵向增长，确认框可滚且操作可达，键盘不遮搜索结果/按钮 |

本项目建议常用及安全按钮**命中区域至少44×44 iOS pt**（暂停也不按次要按钮缩小），视觉图标可小于命中区域。44pt不是44个Unity逻辑px、44个屏幕像素或网页CSS px；必须结合实际panel坐标和设备验证。该项目选择比Apple部分次要游戏控件的28pt建议更保守。[Apple游戏控制指南](https://developer.apple.com/design/human-interface-guidelines/game-controls)

布局按实际可用宽/高、安全区和内容需求变化，不把“iPad一定宽、iPhone一定窄”写死。[Apple布局指南](https://developer.apple.com/design/human-interface-guidelines/layout)；Unity的Screen.safeArea以窗口像素、左下角为原点，UI Toolkit还需坐标转换与panel缩放，不能把点值直接相减。[Unity safeArea](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Screen-safeArea.html)

飞行布局应明确最小可玩区域；若极窄窗口确实无法同时容纳双杆和暂停，先清输入并安全暂停，说明调整窗口方法，不能无提示裁杆或继续飞。这是待测试的降级方案，不是取消iPhone竖屏要求。

## 6. 场景真实感的实现方向

当前`Packages/manifest.json`没有URP依赖，GraphicsSettings的CustomRenderPipeline为空；按当前Built-in与自定义shader审查。**不要把URP/HDRP当成已接入事实或贴图优化的必需前置。** 是否迁移需另列成本、shader/水面/透明/阴影/移动兼容回归。

优先做可核对的材质样板而非任意加图：岸边岩石、干湿沙地、草地/土壤、树皮/针叶、混凝土/沥青、水面/岸线。为每项记录真实覆盖尺度、颜色空间、Normal方向、粗糙/光滑度通道、mipmap/压缩、授权和版本；叠加宏观颜色变化减少重复。法线改善小细节的受光，但山体轮廓、桥梁结构与植被体积必须靠几何，不能由法线贴图替代。[Unity法线说明](https://docs.unity3d.com/6000.3/Documentation/Manual/StandardShaderMaterialParameterNormalMap.html)

在同一条固定低空航线检查起飞区、岩壁、岸线、树冠和远山；观察真实运行中的纹理游动、接缝、高光、阴影和LOD切换。先冻昼间无风对照，再加黄昏、雨湿等变化，不能比较两张不同相机/曝光的图来宣称提升。太阳光、环境光和材质响应一起校准，不把烘焙在颜色图里的高光/阴影重复乘上动态光。

三端共享场景语义但画质档独立：先提出性能预算，再在支持设备上测定纹理驻留、CPU/GPU帧时间、热稳定性和LOD；可降低反射/阴影距离或远景密度，但不能改变任务目标、地标位置和碰撞。预算细节在专项场景报告中，均为候选值而非测量结果。

新环境素材采用原创/自摄或明确可用的授权素材，逐项记录来源与许可；不抓取DJI资产或Google地图影像拼成离线贴图。Mavic 4 Pro等审核位图仍待逐型确认，真实场景调研不扩大为最终机型批准。

## 7. 下一批开发与验收次序

1. **逻辑基线**：页面程序员与共享核心负责人冻结动作ID、SessionDraft、输入来源/owner/暂停/中立恢复，独立QA按相同动作从三入口复跑。正常菜单、飞行、暂停、回放、文字输入上下文逐项区分。
2. **移动布局样板**：UI美术先给iPad宽/窄、iPhone横/竖的首页/选机/飞行/暂停/设置稿；保留桌面23原图，新移动稿需建立明确目标再实现。不能用实际截图反写目标。
3. **真实场景样板**：场景美术做米尺度与材质组合，另一美术复核颜色/光照/重复；页面程序员不拿菜单照片代替3D。先一张完整样板验收，再扩地图。
4. **冻结构建与独立QA**：每条设备线分别构建/安装、输入/安全区/横竖屏/大字/控制器/性能验证，源、构建、设置、场景和设备型号/OS留证。
5. **交付**：每批显式选文件、测试、commit、push及远端SHA；1.25最终仍需用户验收。未确认机型不接新正式飞行，不用版本号/自动检查计数掩盖缺口。

建议预检尺寸包括电脑1280×720/1440×900/1920×1080、移动逻辑布局390×844及交换宽高、430×932及交换宽高、768×1024/1024×768和1024×1366/1366×1024、iPad窄窗口。它们是布局测试样例，不是对应机型列表或真机测试；safeArea、point映射和系统文字设置必须来自实际运行。覆盖边界尺寸、所有UI/HUD档、Text100/125/150/200；先全档自动预检，再以最小/最大组合和触点/安全场景做人工设备复核，不能仅测对角线组合就称全矩阵通过。
