# UI / 缩放 QA 对照基线

2026-10-05 为只读诊断；2026-10-07 根据用户要求修复产品 UI 并复测。两轮使用相同的设计数值基线，不用改变设计要求的方式制造通过结果。

## 基线优先级

1. 产品设计文档第 18 章的明确数值/流程是“设计一致性”断言。
2. 原始 assets/ 美国版效果图用于人工比较页面信息架构、位置与视觉层级，不做逐像素匹配。它们是 AI 设计效果图，不是可执行 Figma 的组件尺寸 oracle。
3. 已交付的 0.4 多机型应用用于回归“实际交付能力”：六机型、预选、启动、暂停、回放。更新机型内容不免除原定 UI 规范。
4. 0.2/0.3 的实现截图只是历史快照，不能用它们替代原始设计并宣称像素级一致。

几何检查以真实 UI Toolkit worldBound / 字体排版数据为依据。正常的长页面纵向滚动不是失败；检查关键操作滚动后是否完整可见。文本排版测量为自动疑似裁切检测，失败需结合截图检查，不能把全部测量差异当成已确认的视觉缺陷。

按钮高度容许 1 个物理像素的 UI Toolkit 布局取整（新原始断言也注明容差）；row-icon 的图标字形不按正文最小字号计错。按钮“至少 44”检查是最低可操作尺寸，不代表每个自动重排的按钮严格等于 44。放大文字时允许按钮增高。

## 缩放与设备定义

2026-10-05 的 80/90/100/110/125/150% 是 QA 注入。2026-10-07 改为调用实际产品的 UI Scale / HUD Scale 设置路径；额外检查 DropdownField 原生回调、即时生效、存档重新载入、从飞行返回时恢复菜单倍率。缺少用户设置仍判 FAIL。

2026-10-07 的 200% 文字使用实际 Text Size 设置及产品字体更新路径，仅放大字体、让容器重排，不放大图片。设置必须包含可选择的 200% 档位。

桌面不同窗口尺寸、UI 倍率、模拟 2×/3× DPI 分别记录。它们不是 OS 显示缩放验证或 iOS 真机测试。不能把窗口截图称为设备截图或把变小窗口称为提高缩放比例。

## 应用和数据隔离

2026-10-05 记录了已交付 0.4 与旧源码不一致的问题。2026-10-07 已恢复同一任务原有六机型脚本并统一为 0.4.0；先从修复源码编译隔离候选，再复制候选并注入诊断入口。旧应用在验收前不覆盖，验收后以可恢复备份保存。旧 aggregate.mjs 只适用于历史交付件；当前报告使用 aggregate-ui-fix.mjs。

暂停/确认面板使用有界 ScrollView。检查滚动视口在屏幕内，以及每个按钮 ScrollTo 后完整可见；不要求整段长内容同时显示。HUD 新增文字子元素必须处于信息卡内部的边界断言。

所有测试使用独立 --data-dir；结果页/报告/回放使用标明 QA fixture 的合成记录，不是用户成绩。测试不读取或改写真实用户存档，也不发布或上传用户数据。
