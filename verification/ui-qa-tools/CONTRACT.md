# UI / 缩放 QA 对照基线

本轮只测试和记录，不改产品 UI，不用改变设计要求的方式制造通过结果。

## 基线优先级

1. 产品设计文档第 18 章的明确数值/流程是“设计一致性”断言。
2. 原始 assets/ 美国版效果图用于人工比较页面信息架构、位置与视觉层级，不做逐像素匹配。它们是 AI 设计效果图，不是可执行 Figma 的组件尺寸 oracle。
3. 已交付的 0.4 多机型应用用于回归“实际交付能力”：六机型、预选、启动、暂停、回放。更新机型内容不免除原定 UI 规范。
4. 0.2/0.3 的实现截图只是历史快照，不能用它们替代原始设计并宣称像素级一致。

几何检查以真实 UI Toolkit worldBound / 字体排版数据为依据。正常的长页面纵向滚动不是失败；检查关键操作滚动后是否完整可见。文本排版测量为自动疑似裁切检测，失败需结合截图检查，不能把全部测量差异当成已确认的视觉缺陷。

汇总时对按钮高度容许 1 个物理像素的 UI Toolkit 布局取整，保留原断言；row-icon 的图标字形不按正文最小字号计错。按钮“至少 44”检查是最低可操作尺寸，不代表精确符合设计的 44；当前主按钮常用 56，另列人工设计偏差。

## 缩放与设备定义

80/90/100/110/125/150% 是 QA 在隔离副本中强制设置 PanelSettings.scale，让同一套真实界面重新布局，不是已有用户缩放功能。用户设置缺失仍判 FAIL。

200% 文本压力测试仅放大字体、不同比例放大图片/布局；也属于 QA 注入，不意味着产品提供 200% 功能。

桌面不同窗口尺寸、UI 倍率、模拟 2×/3× DPI 分别记录。它们不是 OS 显示缩放验证或 iOS 真机测试。不能把窗口截图称为设备截图或把变小窗口称为提高缩放比例。

## 应用和数据隔离

当前工作区有已交付 0.4 与旧源码不一致的问题，本轮不自动恢复或覆盖源码。QA 工具从已交付 app 复制临时测试版本，只注入 QA 入口并添加诊断 assembly；保留原资源/渲染/界面代码，记录原 DLL 与 resources.assets SHA-256 前后不变。

所有测试使用独立 --data-dir；结果页/报告/回放使用标明 QA fixture 的合成记录，不是用户成绩。不发布或上传任何数据。
