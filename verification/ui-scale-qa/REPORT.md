# AeroSim UI 多尺寸 / 多缩放 QA

日期：2026-10-05。被测件：已交付的 macOS AeroSim 0.4.0 的隔离副本。

## 结论

**不通过原产品设计文档的一致性验收。** 启动、暂停和继续点击流程通过，不代表视觉设计和所有关键动作都通过。共整理 11 项已确认问题，其中 1 项为源码/交付版本的可复现性问题；没有在本轮修复或改写设计要求。

打开 [图文对照报告](../../AeroSim-UI缩放QA.html)，可以选择尺寸、UI 倍率、文本倍率和页面，对比原始设计效果图与真实应用截图。

## 尺寸与倍率

- 桌面 1280×720、1920×1080、2560×1440、2520×1080（21:9）、2560×1080（PRD 指定）、3840×2160 全屏：各测 80/90/100/110/125/150%。
- 1680×945 请求实际生成 1680×946；按真实高度记录，六档均测试。
- 4K 窗口请求被系统限制为 3840×1992；六档结果保留，并额外使用全屏模式完成真实 3840×2160 六档测试。
- 1280×720 和 1920×1080 各加一次字体 200% 压力测试，UI 保持 100%。
- 1024×768、844×390、390×844：100% UI。
- 2048×1536 / 200% UI，等效逻辑视口 1024×768；2532×1170 / 300% UI，等效 844×390。这是桌面 DPI 模拟，不是系统显示缩放或移动真机验收。

80–150% 通过 QA 代码改变真实 UI Toolkit `PanelSettings.scale` 并重新布局，不是缩放截图。字体 200% 每个元素只放大一次，不把字体和图片一起缩放，也不会在暂停界面重复放大到 400%。这些注入能力不代表用户设置已实现。

## 已确认问题与复现

### UIQA-01 · P1 · 缩放设置缺失

1920×1080 / 100% → Settings。只有 `Larger UI text`，没有六档 + Auto、独立 HUD Scale 和 200% 文本设置。依据 PRD 18.4.3、18.16。

### UIQA-02 · P1 · 飞行 HUD 遮挡

1280×720 / 100% → 开始飞行：键位提示压住高度/速度读数，电量卡与地图相交。1920×1080 / 125% 也出现遥测/提示条相交。720p / 150% 的遥测卡侵入中央关键视野；竖屏摇杆覆盖底部动作。依据 PRD 18.4.2、18.21。

![720p HUD 实际重叠](desktop-1280x720/100-text1-Aerial-Flight.png)

### UIQA-03 · P1 · 手机横屏暂停动作不可达

844×390 / 100% → Pause：`Exit Without Saving` 从 y=376 到 y=420，屏幕只有 390 高，且该面板没有滚动。3× DPI 等效布局同样复现。暂停面板自身在屏幕内，不能因此忽略越界的子按钮。

![横屏暂停菜单底部裁切](phone-landscape-844x390/100-text1-Aerial-Pause.png)

### UIQA-04 · P1 · 手机竖屏回放返回按钮裁切

390×844 / 100% → Replay：`Back to Records` 从 x=302 到 x=452，超出 390 宽度 62。

### UIQA-05 · P1 · 字体 200% 真实重叠与裁切

1920×1080 / UI 100%、文字 200% → 航拍 Home：进度和描述重叠，原本的 `Start Training` 不再显示，右侧卡片文字裁切。依据 PRD 18.16。属于压力验证，产品目前没有此设置。

![200% 字体压力测试](desktop-1920x1080/100-text2-Aerial-Home.png)

### UIQA-06 · P2 · 基础组件尺寸/位置不一致

100%：菜单顶栏 76，而文档 64；导航展开 216 / 收起 66，而文档 240 / 72。HUD 顶栏 64 / 底栏 68，超过 48 / 56 上限。小地图在右上，设计在左下。主按钮通常高 56，而设计表规定 44；“至少 44”的可点击尺寸检查通过不等于精确尺寸一致。依据 PRD 18.4、18.5、18.6。

### UIQA-07 · P2 · 宽屏内容没有最大宽度

3840×2160 / 100% → Free Flight：文字栏、设置控件与图片无限拉长；`main-content` 超过 3600。文档要求最大宽度 1600，多余宽度用于场景预览。

### UIQA-08 · P2 · 核心页面结构偏离原设计

这类问题不是缩放回归，而是设计实现欠账：

- 自由飞：纵向表单，缺少大场景 + 场景选择卡 + 右侧设置 + 固定启动区。
- 设置：单列表单，缺少左分类和右实时预览。
- OSD 编辑器：单预览区，缺少左组件库和右属性栏的三栏结构。
- FPV 首页：通用内容页，不是全屏背景与中央快速飞行主动作。
- 专业飞行：通用左摘要，没有设计的右侧任务列表/证据区域。

依据 PRD 18.5.4、18.8.3、18.9.1/5、18.10.5。图文报告可逐页对照。原图的实时联网/GPS 数字仅为示意状态，不要求离线应用伪装具备能力。

### UIQA-09 · P2 · 部分文字小于 12

首页推广卡的小标题和 HUD 的 SPEED / ALTITUDE / TIME / BATTERY 标签为 11。依据 PRD 18.3.2；`SET` 图标字形不算正文。

### UIQA-10 · P1 可复现性 · 源码与交付版本不一致

交付 app 的 `CFBundleShortVersionString` 是 0.4.0，运行可见六种机型；当前 `ProjectSetup.cs:29` 是 0.3.0，`AircraftCatalog.cs`、`AircraftVisualModel.cs`、`AeroSimApplication.Hangar.cs` 缺失，仅有 `.meta`。设置页内文仍称 AeroSim 0.2。

本轮没有恢复/覆盖这些源文件。测试从已交付 app 复制 QA 副本，用 Mono.Cecil 只添加 QA 入口并注册诊断 assembly，保留产品 UI/资源。不能用当前旧源码重新构建后宣称测试了原交付 0.4。

### UIQA-11 · P2 · 美国单位显示不一致

U.S. Customary 模式下，风速 mph、飞行高度 ft，但自由飞 `RTH altitude` 仍标 m。依据 PRD 18.6.3 的同一任务单位一致性。

## 隔离、证据与复现

所有运行使用独立 `--data-dir`，结果/报告/回放数据标明 `QA fixture — not a pilot achievement`；没有把测试成绩写入用户飞行档案。原 app 未重新编译或覆盖，前后校验相同：

- `AeroSim.Runtime.dll`：`fc0fc875807222e359d53b68cec41b92a2cdf8cdfaec844e3bd3c0744efb2f07`
- `resources.assets`：`492bc1253b545e377cc3b348570d7f0b6cd728100355474bfd093b639da9a130`

工具位于 `verification/ui-qa-tools/`：

1. `bash verification/ui-qa-tools/build-qa.sh`：复制临时 app，编译并注册 QA assembly，输出临时路径。
2. `bash verification/ui-qa-tools/run-qa.sh /private/tmp/aerosim-uiqa.XXXXXX/AeroSim-UIQA.app`：在各尺寸、倍率和隔离数据目录执行测试。
3. `node verification/ui-qa-tools/aggregate.mjs`：生成图文 HTML、summary.json、failures.json、matrix.csv。

各组保留 `report.json`（UI 几何、文字、断言）、`player.log` 与截图。生成报告的脚本/图片路径和下拉选择逻辑有本地校验；报告 HTML 尚未在浏览器里进行完整视觉验收。

## 不在本轮完成范围

未覆盖 Windows 实机、iOS/iPadOS 真机、系统动态字体/显示缩放、VoiceOver、安全区刘海、所有 hover/focus/loading/error 状态、所有弹出菜单、向导其余步骤、完整键盘/遥控器导航、WCAG 色彩对比或机型模型精度。不能据此签署“全平台全部交互通过”。

建议先核实 0.4 对应源码，再修复 P1 的 HUD/动作可达性/缩放与文本布局问题，随后按原设计逐页补齐结构，最后重复本矩阵并补真机验证。
